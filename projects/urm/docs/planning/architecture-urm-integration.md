# Architecture-to-URM integration instructions

**Review basis:** `6f3ec0d` (2026-09-25). This is the corrective implementation context for the architecture modules that currently execute their mixer without a public URM call. It supplements the [roadmap](roadmap.md), [compiler charter](../compiler/compiler-charter.md), and [evidence rules](../validation/evidence.md). It grants no coverage or performance qualification by itself.

## Review verdict

The absence of a URM call has different meanings across these files. A source-equation reference is useful, but an architecture recipe naming a K1/K2 operation does not make that operation execute. Preserve independent source references while moving only reusable, closed mixer semantics into the public compiler path. Do not add an architecture-name dispatch, opaque callback, or backend branch for a single source model.

The [architecture-recipe schema](../../recipes/schema/architecture-recipe.schema.json) currently requires `kind: complete_model_graph`, while all 54 architecture manifests are marked `generic_model_integration`, `validated: true`; 52 contain only one layer entry. The [loader](../../src/urm/frontend/recipes.py) validates names and order but does not instantiate a model, connect state/cache edges, or execute operations. These documents must report **implementation scope** (equation reference, public callable composition, source-faithful block, or complete model) separately from **execution tier** (public URM reference/native, external Torch, or library) and **evidence mode**. A complete-model kind requires an executable model arrangement and source-model qualification, not merely a named class. Correct existing manifests and tests in place; do not maintain a parallel transitional catalog.

## Exact composition to implement first: HLA

For the masked, causal, unnormalized second-order law of [HLA Theorem 3.1](https://arxiv.org/pdf/2510.27258), define

```text
S_t = S_(t-1) + k_t k_t^T
r_t = S_t q_t
F_t = F_(t-1) + r_t v_t^T
o_t = q_t^T F_t
```

The paper's correction form satisfies `F_t = S_t C_t - G_t`: expanding the right side gives `F_t = sum_(j<=t) (S_j q_j) v_j^T`. The first additive K2 call uses `(query=q, key=k, value=k)` and emits `r_t^T = q_t^T S_t`; the second uses `(query=q, key=r, value=v)` and emits `o_t`. Both reads are after-update and both initial/final states are explicit. The symmetric `S_t` makes the first output orientation exact. The second call can append a constant `1` to each value to produce the optional normalization denominator in [Eq. 3.4](https://arxiv.org/pdf/2510.27258), followed by explicit `epsilon` division outside K2.

Implement this as a two-node public graph with producer/consumer and separate `S` and `F` state edges. Compare output, both final states, every input VJP, and two-chunk continuation against the paper equation and an independent high-precision reference. Include the intermediate `r` materialization, two launches, backward and state traffic in cost. Fusion is a later proved rewrite if those costs matter; it must not be necessary for semantic coverage. The existing [HLA test](../../tests/test_architectures_hla.py) checks two forms of the external recurrence but does not test these public K2 calls.

## Other reusable semantic work

1. **Mamba-2 matrix K2.** For its scalar-per-head transition, test the mapping `M_t = exp(A_h dt_t) M_(t-1) + B_t (dt_t x_t)^T`, `y_t = C_t^T M_t` with `M[N,P]`, head decay, additive write, after-update read, and scale one. Parameter generation, convolution, skip, output gate, and model arrangement remain external. Verify against the pinned recurrent and chunked SSD forms, including nonzero state and continuation, before changing the [Mamba recipe](../../recipes/architectures/mamba.json). The [SSD paper](https://arxiv.org/pdf/2405.21060) distinguishes Mamba-2's scalar transition from Mamba-1's diagonal transition.
2. **Mamba-1 diagonal K2.** Its gate `exp(dt_d A_(d,n))` varies over both state dimensions and cannot be represented by the current [row/head-gated `LinearDeltaSpec`](../../src/urm/ir/program.py). Define a closed elementwise affine transition and read law, with state `[B,D,N]`, step/discretization operands, initial/final state and VJP. Reuse the existing [native diagonal recurrence](../../src/urm/backends/triton/k2.py) only through a correctly bound public descriptor/provider; a direct function call does not qualify a public graph path. Demonstrate another structurally independent client or a nontrivial synthetic cross-axis graph before admitting a new physical branch. Fusing coefficient generation with scan is a performance question, not an equation change.
3. **PAttention K1.** Express score map, normalization rule, normalization order, and source domain as separate closed semantic fields. The pinned variants are `exp(scores)/L1 * count`, `GELU(scores)/L2 * sqrt(count)`, and `GELU(scores/L2 * sqrt(count))`; the last normalizes before the activation and may require a second score pass or retained tiles. ReLU, SiLU and other maps are candidates only after exact denominator, signed-weight, zero-norm, mask, gradient and numerical policies are specified. Reuse the existing [K1 reducer axis](../../src/urm/ir/program.py) rather than a PAttention branch. Before extending it, fix [native K1 provider selection](../../src/urm/backends/triton/k1.py): its `decline` presently checks neither score nor reducer law, while `execute` always invokes online softmax. Unsupported descriptors must decline before execution. Compare public K1 against the pinned PAttention layer and measure the complete parameter-token contraction.
4. **Log-linear state bank.** Define a reusable banked-state lifecycle: dyadic level identity, token/chunk boundary, promotion/reset, per-level scale/read, and cache continuation. Prove equivalence to the source hierarchy at lengths crossing powers of two and at arbitrary partial chunks. The current full-matrix reference is an oracle only. The [log-linear attention paper](https://arxiv.org/pdf/2506.04761) gives logarithmic-space recurrence and chunkwise training; a bank of separately launched K2 calls may erase the gain. Benchmark a batched/fused level schedule before native admission. Add an independent nontrivial client beyond the two files sharing the same mixer.
5. **PaTH score transform.** Describe the strictly causal ordered Householder product, compact block representation, score-tile interface, state/position offsets, and VJP separately from K1 softmax. A dense `score_bias` formed from a full `T x T` correction is a reference path, not an efficient lowering. The [PaTH paper](https://arxiv.org/pdf/2505.16381) describes a blockwise right-to-left score scan that updates online softmax without materializing every score. Verify single- and multi-chunk source parity, then test whether the transform also serves an independent client. Keep DeltaFormer's strict value correction distinct until an exact common operator and schedule are shown.
6. **H3/Hyena ordinary operation.** Share causal FFT convolution, filter/cache contract and prefill/decode cost outside the three mixer families. If a source-specific SSM kernel later has an exact compact-state form, evaluate that as a separate K2 rewrite. External FFT composition counts as external model execution, not internal three-family mixer coverage.

## Acceptance and claim rule

For each candidate, record the exact public graph, descriptor/roles, accepted and rejected cross-products, provider decline behavior, output and all state/operand gradients, nonzero-state continuation, source parity, and paired training/prefill/decode cost. Qualify reference, native, library and external-Torch paths separately. An axis may enter IR/reference before a performant native schedule exists; it cannot be reported as native coverage until that schedule passes the [backend admission rule](../compiler/compiler-charter.md#backend-branch-admission).

Also repair the adjacent [MoM](../../architectures/mom.py) routing error before counting its K2 composition: each memory currently processes the full token stream, so an unrouted token can change that memory's state before a routed token reads it. A test must compare packed routed streams or prove noninterference for tokens not assigned to a memory; recomputing the same full-stream implementation does not establish source parity.
